# 주석 규칙

한 번 정하고 계속 이 안에서만 고르기. 새 태그 만들지 않기.

## 1. `// [영단어]` — 코드 스캔용 (표준 목록 안에서만 골라 쓰기)
눈으로 훑을 때 "이 블록이 뭐 하는 구간인지" 즉시 인식하는 용도.
**두 개 겹쳐 쓰지 않기** — 두 개 필요하면 코드 블록을 나누는 게 맞음.

```
[Init]        초기화
[Validation]  값 검증 (null 체크, 조건 확인 등)
[Insert]      데이터 추가
[Update]      데이터 수정
[Delete]      데이터 삭제
[Cleanup]     정리/해제 (이벤트 리스너 해제, 캐시 비우기 등)
[Capture]     리소스 점유/캡처 시작
[Release]     리소스 해제
[Rule]        실행 순서/규칙 명시
[Convert]     형 변환, 데이터 가공
[Optimize]    성능 최적화 관련
[Calculate]   또는 [Compute]. 좌표 연산, 충돌 판정, 행렬 변환 등 수학적/논리적 연산 블록.
[Render] (또는 [Draw]): 화면에 시각적으로 그리는 작업이나 DOM/Canvas 업데이트 로직.

[Event]: 이벤트 리스너 바인딩, 혹은 이벤트 객체(e.target, e.preventDefault())를 직접 다루는 최상단 처리부. 
```
필요한 태그 추가되면 여기에 등록하고 씀. 애매하면 새로 만들지 말고
가장 가까운 기존 태그로 퉁치기.

## 2. `// NOTE:` — 문제 아님, 알아두면 좋은 배경/이유
버그도 할 일도 아니고 그냥 "왜 이렇게 짰는지" 기록. 해결할 필요 없어서
계속 남아있어도 되는 주석.

```typescript
// NOTE: 아이패드에서 두 손가락 줌 중 한 손가락 먼저 뗄 때 
// pointerup이 한 번 더 발동하는 특이 케이스라 count로 방지함.
```

## 3. `// FIXME:` — 확인된 버그, 아직 못 고침
반드시 나중에 고쳐야 하고, **고치면 주석 삭제**. 코드 전체에서 `FIXME`
검색하면 안 고친 것 전부 나오게 하는 목적.

```typescript
// FIXME: 갤럭시 터치 환경에서 두 손가락 뗄 때 마지막 뗀 손가락 
// 위치로 순간 점프하는 버그. pointerup보다 zoom이 늦게 발동하는 게 원인.
```

## 4. `// TODO:` — 아직 구현 안 한 것
빈 함수나 미완성 로직에 붙여서 "구현 예정" 표시.

```typescript
private Multiselect() {
    // TODO: 다중 선택 로직 구현
}
```

## 5. 태그 없는 주석 = 삭제 예정
사고 과정, 설계 고민, 비유 설명 등 — 결정 근거는 코드가 아니라
`docs/decisions.md` 같은 별도 MD 파일로 옮기고 코드에서는 지움.

---

## JSDoc(`/** */`)은 이 규칙과 별개
클래스/공개 메서드 상단의 JSDoc은 위 태그 시스템을 쓰지 않고
`@description`, `@param`, `@example`로만 구성. 대괄호는 여기선 안 씀
(코드 스캔용 태그와 혼동되지 않게).

## 빠른 판단 순서
1. 남한테 설명 근거로 필요한 배경/이유인가? → `NOTE`
2. 확인된 버그, 아직 못 고쳤나? → `FIXME`
3. 아직 구현 안 한 것인가? → `TODO`
4. 코드 블록 종류를 스캔용으로 표시하고 싶은가? → `[표준태그]`
5. 위 네 개 다 아니면 → 안 달거나, 달았어도 나중에 지움
